Full build guide

Sakan — a grounded RAG assistant for Dubai tenancy law
Ask a question about Dubai rental law, get an answer cited to the exact article — or an honest "not covered" instead of a guess. This is everything needed to understand the domain, scope the build, and ship it in six days.

Domain research

What's actually true about Dubai tenancy law
Verified before writing this guide, so the project is built on real, current facts rather than assumptions — and so you can speak to the domain accurately in an interview.

Verified via search — Aug 2026
Dubai's rental relationship is governed by Law No. 26 of 2007 ("Regulating the Relationship Between Landlords and Tenants in the Emirate of Dubai"), amended by Law No. 33 of 2008 — primarily affecting rent-increase mechanisms and eviction notice requirements.
Decree No. 43 of 2013 introduced the tiered rent-increase calculator, linked to the RERA Rental Index, which caps permissible annual increases on a sliding scale depending on how far current rent sits below the index.
All lease contracts must be registered with Ejari, Dubai's official lease registration system — an unregistered contract cannot be used to legally enforce a rent increase.
The official law text is published by the Dubai Land Department's legislation portal, and DLD also publishes a plain-English Tenancy Guide.
Don't hardcode the exact percentage bands. The rent-increase calculator's tiered thresholds can be adjusted by decree, and a demo that states a specific number confidently and gets it wrong is worse than one that cites its source. Pull the current bands directly from the DLD calculator page at build time and cite the decree, don't rely on this guide's summary for exact figures.

Problem & users

Why this, for whom
Tenants and small landlords in Dubai overwhelmingly get rental-law answers from blog posts and agent hearsay rather than the primary text — which is public, but written in legal register and scattered across a law, an amendment, and a decree. Sakan collapses that into a direct, cited answer.

Who it's for
A tenant checking whether a rent-increase notice they received is legally valid
A landlord or agent confirming notice-period requirements before a non-renewal or increase
The evaluator: a hiring engineer at a proptech or legal-tech company, judging whether you can build a retrieval system that doesn't hallucinate — the single most-tested property of a RAG system in an interview
Architecture

How it works, end to end

Parse & clean source PDFs, chunk by article boundary
→
02 INDEX
Embed chunks + build a BM25 keyword index in parallel
→
03 RETRIEVE
Hybrid search, merge & rerank top candidates
→
04 GENERATE
Answer only from retrieved context, cite article no.
→
05 VERIFY
Check citation actually supports the claim, else refuse
Why article-boundary chunking, not fixed-token windows
Legal text is punished by naive fixed-size chunking — an article's operative clause can get split from its heading, or two unrelated articles get merged into one chunk, both of which corrupt citations. Split on structural markers (Article (\d+)) and keep the article number + title as metadata on every chunk.

def chunk_by_article(raw_text: str) -> list[dict]:
    articles = re.split(r'(?=Article\s*\(?\d+\)?)', raw_text)
    return [
        {"article_no": extract_article_no(a), "text": a.strip()}
        for a in articles if a.strip()
    ]
Why hybrid retrieval, not vector-only
Legal questions often reference exact defined terms ("Ejari," "Article 25," "RERA Rental Index") that keyword search nails and pure embedding similarity can blur. Merge both with reciprocal rank fusion.

def hybrid_search(query: str, k: int = 6):
    vector_hits = vector_index.similarity_search(query, k=k)
    keyword_hits = bm25_index.search(query, k=k)
    return reciprocal_rank_fusion(vector_hits, keyword_hits)[:k]
Generation prompt — the guardrail is the point
SYSTEM:
Answer only using the provided articles below.
Cite every factual claim as (Article N).
If the articles do not contain the answer, reply exactly:
"Not covered by this source set."
Never state a specific percentage or figure unless it
appears verbatim in the provided context.
Tech stack

What to actually install
Layer	Choice	Why
Orchestration	langchain or plain Python	Either works at this scale — plain Python is fine and easier to explain in an interview
Vector store	chromadb (local) or FAISS	Free, no infra, good enough for a corpus of a few hundred pages
Keyword index	rank_bm25	Lightweight, no server needed
LLM	OpenAI or Anthropic API (small/cheap model)	Grounded generation from short context doesn't need a frontier model — keep cost low
Eval	deepeval (pytest-native) + RAGAS faithfulness metric	DeepEval gives you CI/CD-style "tests pass" evaluation — a very legible artifact for a README
UI	Streamlit	Fastest path to a deployed, clickable demo
Deploy	Streamlit Community Cloud	Free, one-click from a GitHub repo

Evaluation

This is the part that gets you the callback
Most junior RAG projects skip evaluation entirely. A scored eval set with a faithfulness metric is the single highest-leverage thing you can add.

# eval/test_faithfulness.py
from deepeval import assert_test
from deepeval.test_case import LLMTestCase
from deepeval.metrics import FaithfulnessMetric

def test_rent_increase_notice_question():
    case = LLMTestCase(
        input="How much notice must a landlord give before increasing rent?",
        actual_output=sakan_answer(...),
        retrieval_context=retrieved_chunks(...),
    )
    assert_test(case, [FaithfulnessMetric(threshold=0.8)])
Include a handful of deliberately out-of-scope questions ("What's the rent law in Abu Dhabi?") to verify Sakan refuses instead of guessing — a passing refusal test is as valuable in the README as a passing factual test.
